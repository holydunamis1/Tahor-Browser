# Decisions

Every decision is recorded here with its reason. Decisions D-01 to D-30 come from the final blueprint (section 22). D-31 onward were made while building. Additions only; a superseded decision is marked, not deleted.

The `BLOCKLIST_SIGNING_KEY_B64` secret first held the raw seed bytes instead of their base64 text, which made GitHub refuse to start any workflow that used it; it was re-stored as base64 text with the same seed | Recorded so the failure mode is not repeated | B14 |
| D-99 | The compiler emits WebKit rule lists of at most 50,000 rules (WebKit's own limit is 150,000), with exceptions (`ignore-previous-rules`) after the blocks of every list, one `css-display-none` rule per selector (so one invalid selector cannot invalidate a merged rule), and per-site exceptions appended to every list. | D-100 | The Android compiler merges host blocks into alternation patterns of 400 hosts, keeps other rules one by one, caps the total at 5,000 entries (counting the excess), drops exceptions (counted), and leaves element hiding to `CosmeticFilter`. Whether this cap gives acceptable load time is decided by the B17 performance gate, not assumed | Android's matcher slows with many entries; the cap is a starting value | B15 |
| D-101 | A refresh downloads the manifest and its signature first; the list is downloaded only when the signed manifest is strictly newer than the list in use. Equal or older is "up to date", never an error and never applied. The saved list is verified again at every start, and any failure falls back to the starter list | A tampered or stale file on disk must not outrank the starter list | B15 |
| D-102 | The starter list inside the app is not verified against a signature: its `manifest.json` describes the full list, and the starter is a subset. It is trusted because it is part of the signed app binary | The seed is not the list the manifest hashes | B15 |
